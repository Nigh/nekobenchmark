<h1 align="center">SyncRateBench</h1>

<p align="center">
  <a href="README.md">English</a> | 中文
</p>

基于 Godot 4 的本地反应、瞄准与跟踪测试工具，支持 Windows、Linux 和 macOS，测量你与电脑共同构成的响应能力。

## 快速上手

从 [Releases](https://github.com/Nigh/SyncRateBench/releases) 下载对应平台的发布包，完整解压后运行。请将随包资源保留在可执行文件旁。程序以全屏菜单启动，应用界面仅提供英文。

- 从菜单左侧选择测试；`History` 和 `Settings` 位于 Tools 区域。
- 测试内按 `Esc` 返回菜单，菜单内按 `Esc` 退出。结果页按 `R` 或点击 `Retry` 重试。
- 反应键为 `Space`、`Z`、`X` 和方向键，鼠标左键也可作答或开火。
- 完成五项测试后，可填写标签，在菜单点击 `Save Session` 保存整组成绩。

## 测试项目

每项测试包含五轮。结果页显示逐轮成绩、中位数、平均值和样本标准差，并通过雷达图展示当前结果与其他项目的最近成绩。

### 2D Reaction

颜色变化后，用反应键或鼠标左键作答。每次随机等待 1–4 秒，响应窗口为一秒。提前输入或超时会作废整套测试。有效响应后立即开始下一次等待。

### 3D Reaction

在固定的低多边形房间内用鼠标观察，水平转向范围为 180°。随机等待 1–4 秒后，目标在一秒响应窗口内穿越掩体。目标处于相机视野内时点击即可，无需准星直接瞄准。提前输入或超时会作废整套测试。

### OSU

命中固定中心绿门启动一轮。随机等待 1–3 秒后，按顺序命中六个编号圆。相邻圆等距，同时仅显示当前及后续两个目标，不透明度分别为 100%、60%、30%；不相邻的圆可能重叠。

点击或按反应键时，光标必须位于当前目标上；目标仍在渐显时也可命中。计时从首个有效命中开始，到最后一击结束，首击后限时六秒。等待期提前输入、未命中或乱序会作废整套测试。未命中绿门不会作废；成功一轮后立即出现下一轮绿门。

### 3D Aim

瞄准并命中中心绿门启动一轮。随机等待 1–3 秒后，同时出现六个互不重叠的球体。五种固定布局以随机顺序各出现一次，目标覆盖四个视角象限。

用鼠标瞄准，鼠标左键或反应键开火，命中球立即消失。计时从目标出现到最后一击。等待期提前开火，或六秒内未清完目标，会作废整套测试。间隔不足 150 ms 的开火被忽略；未命中绿门不会作废。清场成功后立即出现下一轮绿门。

### 3D Tracking

仅需鼠标转向跟住移动目标，无需开火。准备自动开始，准星连续处于外圆内一秒后进入十秒计分阶段。准备时离开外圆会重置累计进度，外缘进度环显示跟踪准备情况。

准备时目标低速移动，计分开始后用一秒恢复全速。五条固定轨迹以随机顺序各出现一次。准星处于黄色内圆的时间计满分，处于外环计半分，圆外计零分。计分时的轻柔高音 / 低音分别提示内圆 / 外环覆盖。

原始成绩为五轮按时间加权的覆盖率中位数，越高越好；同时显示平均角度误差，越低越好。跟丢目标会降低覆盖率。失去窗口焦点会取消整套测试，返回窗口后自动重新开始。比较时应保持显示与帧率条件一致。

## 分数

每项测试将五轮原始成绩的中位数换算为 0–100 分，显示一位小数，同时保留原始毫秒数或加权跟踪覆盖率。分数均为越高越好。五项齐全时菜单显示总分，满分 500；缺项显示 `--`。

| 项目 | 参考分数 |
| --- | --- |
| 2D / 3D Reaction | 50 ms = 100，220 ms = 80，1000 ms = 0 |
| OSU | 500 ms = 100，1800 ms = 70，6000 ms = 0 |
| 3D Aim | 2400 ms = 60，6000 ms = 0 |
| 3D Tracking | 覆盖率 0% = 0，30% = 60，100% = 100 |

Reaction 与 OSU 在锚点间按时间的对数线性插值。Aim 使用 `clamp(60 * ln(6000/t) / ln(6000/2400), 0, 100)`。Tracking 在覆盖率 `c <= 30` 时使用 `60 * ln(1+c) / ln(31)`，之后使用 `60 + 40 * ln(c/30) / ln(100/30)`。所有分数限制在 0–100。

失效或超时的整套测试显示 0.0 分，不替换缓存成绩。完整完成的 0% Tracking 成绩有效。

## 保存与历史记录

菜单保留本次运行中各项目最近一次有效成绩，即使它比上次更差。每项成绩自完成起一小时内可保存。过期成绩仍以淡化样式显示并标记 `EXPIRED`，但不能保存。

`Save Session` 要求五项成绩均未过期且未保存。可选标签最多 64 字符。保存将这五项成绩组成一次测试记录，并清空标签；分数与雷达仍保持显示。再次保存需要重新完成全部五项。保存失败可在原有效期内重试。退出应用后，未保存成绩丢失。

`History` 显示全部整组记录和明确标记的旧单项记录，列表最新在前，每页 50 条。图表按时间顺序显示最近 100 条记录，分数轴固定为 0–100。可用滚轮、触控板横滑或鼠标拖动浏览；悬停柱条查看逐轮成绩及元数据，点击图表组或列表行选择整组记录。详情显示总分、各项目分数与原始成绩、灵敏度、规则版本及雷达图。旧单项只显示真实项目，满分为 100。

每组记录保留各项目完成时间、五轮样本、统计值、灵敏度和规则版本，Tracking 另含角度误差。整组保存时间包含 UTC、本地时间和 UTC 偏移。当前规则版本为 Reaction v1、OSU v3、Aim v2、Tracking v4；比较成绩时请核对版本。

设置保存在本地 `user://scores.txt`，已保存历史在 `user://history.json`。有效的旧 epoch-2 单项记录保留并标记为旧记录。从有效的 pre-epoch-2 数据迁移时会清除旧成绩与历史，保留灵敏度。损坏、无法读取或不支持的文件不会被覆盖。不提供云同步、历史导出、编辑或删除功能。

## 灵敏度与练习

所有 3D 模式共享灵敏度倍率和 103° 水平视野（16:9 下垂直约 70.5°）。灵敏度默认 1.00，范围 0.10–5.00。可在 `Settings` 调整，或通过 `Open Sens Lab` 进入无计分练习：清空呈正方形排列的四球，命中中心绿门即可重新生成。

- 滚轮：每次调节灵敏度 0.05，按住 `Alt` 时为 0.01。
- 按住 `Alt`：释放光标以拖动灵敏度滑条；松开后恢复鼠标视角。
- `-` / `=`：缩小 / 增大正方形间距。
- `[` / `]`：拉近 / 推远目标，每次 0.25，范围 3–20，默认 8。

间距和距离键支持长按连续调整。必要时会缩小间距以保持目标在视野内且互不重叠。底部面板在调整时显现，闲置后淡出。灵敏度、间距和距离均会保存，保存失败恢复原设置与布局。

## 如何解读结果

SyncRateBench 测量的是**人 + 电脑的整条响应链路**，包含显示、输入与系统延迟。有意义的比较应控制变量：

- 不同的人使用同一台电脑：比较玩家响应能力。
- 同一个人使用不同电脑：比较设备影响。
- 同一个人在同一台电脑上、不同时段测试：观察状态变化。

不同的人在不同电脑上的分数无法区分两种因素。计时使用 Godot 的单调微秒时钟，不是屏幕出光时刻的物理测量。显示扫描、像素响应、输入轮询和系统调度无法从成绩中剥离。程序关闭 VSync 和鼠标输入累积以降低软件延迟，因此可能出现画面撕裂。

## 开发与构建

克隆 [SyncRateBench](https://github.com/Nigh/SyncRateBench)，在 Godot 中打开 `project.godot`。项目使用 GDScript、Godot 原生 UI 和 3D 渲染，无需 .NET，当前配置使用 Compatibility 渲染器。发布工作流使用 Godot 4.4.1 及匹配的非 .NET 导出模板。

在仓库根目录导入项目并运行检查：

```sh
godot --headless --path . --editor --quit
godot --headless --path . --script tests/reaction_state_test.gd
godot --headless --path . --script tests/sequence_state_test.gd
godot --headless --path . --script tests/playthrough_test.gd
godot --headless --path . --script tests/history_tracking_test.gd
```

通过 `Linux`、`Windows` 或 `macOS` 导出预设构建发布包，分发时包含全部导出文件，包括独立 `.pck` 资源（如有）。macOS 使用兼容 Intel 与 Apple Silicon 的 Universal 模板。Pull Request 会构建三平台发布包，`v*` 标签或手动运行发布工作流会发布 Release。
